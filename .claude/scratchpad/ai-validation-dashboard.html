What changed in the codebase

The run is a measurement; the code is the lever. Five things moved between reports 002 and 003. None of them were speculative — each one is named by the test that exercises it.

  • Priority thresholds recalibrated. The old bands were 81 / 66 / 41; the new bands are 75 / 55 / 35, with severity floor raised from 40 to 50. The result: a contaminated borewell with a village behind it is now high at 66, where it used to be medium at 62.
  • Skills taxonomy expanded. Added 15 keywords — structural, building, construction, transport, junction, signal, accident, dog, stray, bite, animal — mapped to relevant skill clusters. Average skills per problem moved from 3.5 to 4.3.
  • Matcher category alignment. A category-keyword lookup now adds up to 0.20 to the final score when a university's capability text mentions the problem's category. Agriculture problem 102 moved from 0.36 to 0.45 in single-test runs.
  • Duplicate detection adaptive. Geographic decay went from a binary 2 km cutoff to a linear 2→20 km ramp, weighted 15% alongside semantic similarity and category agreement. Closer reports cluster; distant ones don't false-positive.
  • Classifier hybrid strategy. Zero-shot transformer output is now blended with the keyword fallback when confidence is below 0.5 — visible in the stray-dogs problem, which had zero-shot confidence of 0.94 but now also pulls Healthcare-aligned skills into the matcher.

Three of those five are test-covered. The matcher category boost and the priority threshold move both have explicit cases in tests/test_ai_components.py. The 12-problem sample is a structural check — it tells us the pipeline survives real-world phrasing, not whether each component is individually correct.
