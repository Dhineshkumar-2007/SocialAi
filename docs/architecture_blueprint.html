AI Pipeline Local PyTorch / Transformers

Synchronous execution of BGE-small embeddings, DeBERTa zero-shot classification, BLIP vision captioning, and regex-based skill extraction.

UI / Presentation Jinja2 + Vanilla JS

04 Database Schema Changes

All database modifications follow strict zero-downtime, idempotent migration patterns. Existing tables are preserved, and new columns and tables are added via safe DDL.

New Migration: 002_project_workspace_and_learning_loop.sql

-- 1. Project Milestones & Tasks Table
CREATE TABLE IF NOT EXISTS project_milestones (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    title TEXT NOT NULL,
    description TEXT,
    stage TEXT CHECK(stage IN ('prototype', 'pilot', 'deployment', 'maintenance')) DEFAULT 'prototype',
    target_date TEXT,
    completed_at TEXT,
    status TEXT CHECK(status IN ('pending', 'in_progress', 'submitted', 'verified')) DEFAULT 'pending',
    evidence_url TEXT,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES projects(id)
);

-- 2. Citizen Resolution Feedback & Rating Table
CREATE TABLE IF NOT EXISTS resolution_feedback (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    problem_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    is_resolved INTEGER NOT NULL CHECK(is_resolved IN (0, 1)),
    rating INTEGER CHECK(rating BETWEEN 1 AND 5),
    feedback_text TEXT,
    photo_evidence_url TEXT,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (problem_id) REFERENCES problems(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 3. Matcher Adaptive Learning Adjustments Table
CREATE TABLE IF NOT EXISTS matcher_learning_adjustments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    university_id INTEGER NOT NULL,
    category_id INTEGER,
    skill_name TEXT,
    penalty_factor REAL DEFAULT 1.0,
    sample_count INTEGER DEFAULT 0,
    last_reason TEXT,
    updated_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (university_id) REFERENCES universities(id)
);

06 AI Intelligence Pipeline Architecture

The AI core pipeline executes in five deterministic, cascading stages upon problem submission:

1. Vision Verification
→
2. Dense Embedding
→
3. Zero-Shot Classifier
→
4. Geo-Cluster & Duplicates
→
5. Priority Scoring
Priority Scoring Mathematical Formula
Priority Score = (Severity × 0.35) + (Affected Pop × 0.25) + (Evidence Score × 0.25) + (Duplicate Count Boost × 0.15)
Calibrated Evidence Reliability Discount
When evidence analysis results in low confidence (< 0.40) or contradictory image captions, an automatic 0.70 discount multiplier is applied to matching scores to prevent inaccurate automated dispatching while still allowing manual review.

07 University Matching Engine Design

Matching calculates a composite score $S_{\text{final}} \in [0, 1]$ across five independent evaluation criteria:

Multi-Criteria Matching Weight Matrix
S_final = (S_semantic × 0.40) + (S_skills × 0.25) + (S_labs × 0.15) + (S_projects × 0.10) + (S_capacity × 0.10)
Factor Weight Calculation Method Data Source
Semantic Alignment 40% Cosine similarity between problem text and institutional capability text BAAI/bge-small-en-v1.5 Dense Vectors
Faculty Skills 25% Overlap coefficient between extracted required skills and faculty expertise faculty table (department + expertise)
Laboratory Facilities 15% Keyword & semantic hit rate on specialized research lab infrastructure labs table (name + facilities)
Past Project History 10% Semantic relevance to previously completed societal interventions previous_projects table
Current Capacity 10% Normalized remaining student/faculty bandwidth: $\min(1.0, \text{capacity} / 10)$ universities.capacity

08 Accept / Decline / Re-Routing State Machine

The state machine guarantees deterministic progression with zero orphan challenges. Ranked matches are pre-computed during analysis; re-routing traverses the pre-sorted list without repeating expensive neural inference.

1. Auto-Offer (Rank 1)

Problem state → PENDING_UNIVERSITY_RESPONSE. Assignment record created in status pending. 72-hour countdown timer begins.

2. University Accept

Problem state → IN_PROGRESS. Assignment record → accepted. Project workspace initialized with milestone tracker.

3. Decline or 72h Timeout

Assignment record → rejected with reason logged. System fetches Rank $N+1$ from problem_university_matches.

4. Fallback Boundary

If all $K \le 5$ rounds are exhausted without acceptance, problem state transitions to NO_UNIVERSITY_AVAILABLE and alerts admin for manual allocation.

10 Notification & Communication Architecture

A multi-tiered notification service delivers in-app and webhook alerts on all critical state transitions:

  • assignment_created: Sent to University Lead on initial offer with 72h expiration notice.
  • assignment_expired: Sent to University & Admin when challenge times out.
  • rerouted_notice: Sent to next ranked institution explaining assignment context.
  • project_milestone_submitted: Sent to Admin and Citizen upon milestone completion.
  • resolution_ready_for_review: Sent to reporting Citizen for final verification.

11 Analytics & Continuous Learning Loop

To eliminate repeated mis-assignments, the system implements an active learning loop:

Adaptive Feedback Weighting Engine
When an institution declines an assignment citing "lack of equipment" or "department overcapacity", the matcher dynamically applies a temporary penalty factor $\lambda \in [0.5, 0.8]$ to that category/skill for the next 30 days, re-ranking candidate institutions adaptively.
